## What compiles cleanly

Selecting from Makefile.rumpkern's SRCS + a few extras:
- All the `sys/rump/librump/rumpkern/` support (rump.c, locks.c,
  scheduler.c, threads.c, intr.c, emul.c, ...)
- Bulk of `sys/kern/` (kern_proc, kern_lwp, kern_clock, kern_time,
  kern_tc, kern_timeout, kern_event, subr_kmem, subr_pool,
  subr_prf, subr_vmem, and ~50 others)
- Crypto: blake2, chacha, nist_hash_drbg, cprng_fast
- Secmodel: secmodel, secmodel_extensions, secmodel_suser
- `sys/net/radix.c` — routing radix tree
- `common/lib/libc/gen/radixtree.c` — kernel radix-tree utility

## Deliberately excluded (with reason)

- `atomic_cas_generic.c` — we ship our own PPC lwarx/stwcx atomics
- `locks_up.c` — UP variant, mutually exclusive with locks.c
- `sleepq.c` — rump-local, uses stale `sq_cv` field (predates
  the modern sleepq layout)
- `vm.c` — needs `pmap_kernel`, port-specific
- `rump_autoconf.c` — wants autogenerated `ioconf.c`
- `init_sysctl_base.c`, `subr_autoconf.c`, `sys_generic.c`,
  `uvm_swap.c` — pull in `machine/disklabel.h` (not in
  `arch/powerpc/include/`)
- `kern_ntptime.c` — wants `compat/sys/timex.h`
- Autogen: `rump_syscalls.c`, `rumpkern_if_wrappers.c`,
  `syscalls.c`, `vers.c`, `vnode_if.c`
- Most of `sys/uvm/` — every added `uvm_*.c` brought in more
  unresolved than it resolved (needs a proper VM plan first)

## What this unlocks vs. what's still blocking

Unlocked (compilation-wise):
- The whole kernel synch machinery (mutex, rwlock, cv, sleepq
  shim from rumpuser)
- Process/lwp tracking (kern_proc, kern_lwp, kern_resource, etc.)
- Kernel clock + timers (kern_clock, kern_tc, kern_timeout,
  clock_subr)
- kmem/pool/vmem allocators
- Routing + radix tree data structures
- Crypto (blake2, chacha, cprng, nist_hash_drbg)
- Kauth (secmodel)

Still blocking a `rump_init()` bring-up:
- 144 unresolved symbols
- No autogenerated `rump_syscalls.c` / `rumpkern_if_wrappers.c`
- No entry-point function that actually calls `rump_init()`
- No hookup to a real executable on the OS4 side
