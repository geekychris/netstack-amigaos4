# Rump kernel build probe — findings

First attempt at compiling one rump kernel source file
(`sys/kern/kern_mutex.c`) against our cross-toolchain
(`walkero/amigagccondocker:os4-gcc11-arm64`). This document
records what unlocked each layer of includes and where the
compile is stuck now.

## The compile command

```sh
docker run --rm -v $(pwd):/work -w /work \
    walkero/amigagccondocker:os4-gcc11-arm64 \
    ppc-amigaos-gcc -c \
      -mcrt=newlib -mhard-float -O2 -mcpu=440 \
      -D__PPC__ -D__NetBSD__ -D_KERNEL -DKERNEL \
      -Ivendor/netbsd-rump/sys \
      -Iinclude -Iinclude/netstack -Iinclude/rumpuser \
      vendor/netbsd-rump/sys/kern/kern_mutex.c -o /tmp/km.o
```

## What each iteration unlocked

| Error                                                | Fix                                                          |
|------------------------------------------------------|--------------------------------------------------------------|
| `machine/cdefs.h: No such file or directory`         | Import `sys/arch/powerpc/include`, symlink `sys/machine` → `arch/powerpc/include` |
| `powerpc/int_types.h: No such file or directory`     | Symlink `sys/powerpc` → `arch/powerpc/include` (NetBSD build does both) |
| `lib/libkern/libkern.h: No such file or directory`   | Import `sys/lib/libkern`                                     |
| `uvm/uvm_param.h: No such file or directory`         | Import `sys/uvm` (headers only, for size constants)          |
| `#error unknown PPC variant`                         | **← stuck here.** Need PPC_BOOKE or similar config define    |
| `MIN_PAGE_SIZE not defined`                          | Comes from `opt_*.h` files (see below)                       |

## Where the friction actually lives

NetBSD kernel builds don't feed the compiler include paths
alone. They generate a small forest of `opt_*.h` config files
per-KERNEL-config that pin down every conditional the kernel
uses: which SMP model, which PPC variant, PAGE_SIZE, kernel
address-space layout, feature toggles for every subsystem, etc.

Every non-trivial `.c` under `sys/` starts with
`#include "opt_*.h"` (implicit via `sys/param.h`) and blows up
if those symbols aren't defined.

For a rump kernel port, the rump-specific config lives in:
- `sys/rump/librump/rumpkern/opt_*.h` (generated by rump's build)
- `sys/rump/Makefile.rump` (defines what CFLAGS + opt_*.h to
  synthesize per subsystem)

Reading + porting NetBSD's build.sh path for rump is the next
concrete work. Two ways to proceed:

1. **Read rump's own build machinery** and reproduce the
   opt_*.h files we need for network + kern subsystems. Precise
   and reproducible; needs ~4-8 hours to trace + author.
2. **Try building a rump kernel via NetBSD's build.sh on a
   Linux/BSD host** (`build.sh -m amd64 tools kernel=RUMP`),
   capture the generated opt_*.h files + the actual CFLAGS
   used, port those settings to our Makefile. Faster to get
   *something* building; less clean because we're inheriting a
   different arch's opt_*.h and translating.

## What's actually blocking

Every layer above is header plumbing. The actual OSAL binding —
mapping `mutex_enter` etc. to our `osal_mutex_lock` — hasn't
been touched yet, but that work is largely done (see Phase 1)
and just needs to be exposed via a header shim that maps
NetBSD's `struct mutex` operations onto our `osal_mutex`.

```

        │

        │

```
